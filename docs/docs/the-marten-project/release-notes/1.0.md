_Under development._

## Requirements and compatibility

* **Crystal:** 1.17, 1.18, 1.19, 1.20, and 1.21.
* **Databases:**
  * MariaDB 10.11 and higher.
  * MySQL 8.4 and higher.
  * PostgreSQL 15 and higher.
  * SQLite 3.37.0 and higher.

## New features

### Models and databases

* Query sets now provide a [`#each_batch`](../../models-and-databases/reference/query-set.md#each_batch) method, allowing to iterate over large query sets in batches without loading all the matching records into memory at once. Records are fetched in batches using a primary key cursor and are always processed in ascending primary key order.
* Models and query sets now support pessimistic row locking via `SELECT ... FOR UPDATE`. Query sets provide a [`#lock`](../../models-and-databases/reference/query-set.md#lock) method, while model records provide [`#lock!`](pathname:///api/dev/Marten/DB/Model/Persistence.html#lock!(lock%3ABool%7CString%3Dtrue%2Cusing%3ANil%7CString%7CSymbol%3Dnil)-instance-method) and [`#with_lock`](pathname:///api/dev/Marten/DB/Model/Persistence.html#with_lock(lock%3ABool%7CString%3Dtrue%2Cusing%3ANil%7CString%7CSymbol%3Dnil%2C%26block)-instance-method). See [Pessimistic locking](../../models-and-databases/transactions.md#pessimistic-locking) for more details.
* Multi-database projects can now define pluggable [database routers](../../models-and-databases/multiple-databases.md#database-routers) via the [`database_routers`](../../development/reference/settings.md#database_routers) setting. Routers resolve which database to use for reads and writes, gate cross-database relations, and control which migrations apply to a given database. Model instances also remember the database they were loaded from or saved to when an explicit `#using` selection is used.

### Development

* The [`serve`](../../development/reference/management-commands.md#serve) management command now displays how long project compilation took after each successful build.

## Backward incompatible changes

### Handlers and HTTP

* The default value of the [`trailing_slash`](../../development/reference/settings.md#trailing_slash) setting is now `:remove`, so unresolved URLs ending with a trailing slash are permanently redirected to their slashless version by default. Applications that want to keep the previous behavior should explicitly set `config.trailing_slash = :do_nothing`.
